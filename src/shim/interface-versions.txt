# Interface versions the shim serves with a real, slot-exact MSVC vtable (#20).
#
# This is the UNION of the version strings compiled into the two proof titles'
# Steamworks import libraries — i.e. exactly the set their steam_api can ask for:
#
#   Surviving Mars (3215050)  steam_api64.dll   64-bit
#   Among Us       (945360)   steam_api.dll     32-bit
#
# Regenerate the list for a new title with:
#   strings -a <steam_api[64].dll> | grep -E '^(STEAM|Steam)[A-Za-z]*_?[A-Z_]*(INTERFACE_VERSION)?_?[0-9]{3}$' | sort -u
#
# Mind the irregular ones — the version suffix is not always bare digits:
# STEAMHTMLSURFACE_INTERFACE_VERSION_005, STEAMINVENTORY_INTERFACE_V003,
# STEAMVIDEO_INTERFACE_V002. A tighter pattern silently drops them, and the
# first symptom is a title stopping mid-init on a NULL interface.
#
# Versions matter, not just interfaces: SteamInput006 (Mars) inserts
# SetInputActionManifestFilePath at slot 2 and shifts every later slot against
# SteamInput002 (Among Us). Serving one layout for both calls the wrong method
# with no error (map trap 2), and on i386 also pops the wrong number of bytes.
#
# A version absent here is served NULL on i386 rather than a wrong-arity vtable
# (see acquire() in shim_pe.c). Add it here and rebuild.
